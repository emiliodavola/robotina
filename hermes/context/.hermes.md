# Environment facts for this agent (robotina stack)

Verified facts about THIS container, so they do not have to be re-derived (and
guessed wrong) on every session:

- **You live in your own container.** You share neither container nor filesystem with
  the OpenCode agent, except `/workspace`, which is the same directory for both.
- **You have `git` (2.47), `curl` and `python3`; `gh` is NOT installed.** You have
  **no GitHub credential at all**: no `GITHUB_TOKEN`, no git credential helper, no
  `~/.config/gh`. That is deliberate — the credential lives in the OpenCode container.
- **There is no direct Internet here.** Everything goes out through `egress-proxy`
  with a domain allowlist. A task that needs a new host means editing
  `squid/allowlist.txt` on the host and restarting the proxy: report that, do not
  improvise around it.
- **Public repositories: clone them here.** `git` works through the proxy without
  credentials, and `git@github.com:` URLs are rewritten to HTTPS automatically.
- **Private repositories, and anything that pushes: delegate to OpenCode** over its
  HTTP API — it holds `gh` plus a fine-grained PAT, and it writes to the same
  `/workspace`. The mechanics are in the `opencode-server` skill; the policy is in
  `github-private-repos`.

## Hard rule

**Never ask the user for a GitHub token, and never write a token into a prompt, a
file, a commit or the chat.** The stack already holds one, in the container that
needs it.

A `404` on a private repository means "no credentials on this side", not "the
repository does not exist". The correct conclusion is **delegate**, never "I need a
token".
